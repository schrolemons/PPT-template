# 全局总览目录

## 用途

在封面之后提供整套汇报的章节级方向感：按来源或用户指定顺序列出每个章节、其语义范围，以及最终起始页或最终页段。它是章节概览，不替代任何一章的章内目录。

## 适用与不适用

适用于包含多个章节或需要向听众说明整套叙事范围的汇报。仅使用已冻结的 `structure-map` 中的章节、语义标签和页码信息。

不适用于列出某一章的独立小部分、取代 `chapter-agenda`、补充来源之外的研究主张，或定义内容模块的字段布局。若没有真实的章节结构，不得为了视觉完整性虚构章节条目。

## 输入

- 冻结的 `structure-map`；
- 按用户/来源顺序排列的 `chapter_id`、章节语义标签与范围；
- 每章最终起始页或最终 `page_span`；
- 该页的 `instance_id`、`narrative_role`、`source_refs` 和备注要求。

## 输出

生成一个 `whole-deck-overview` 实例，逐项呈现：章节的可读语义标签、该章覆盖的语义范围、最终起始页或最终页段。输出连接字段至少包含 `module_id`、`instance_id`、`chapter_id`（整套层级可为空）、`section_id`（整套层级可为空）、`subsection_label`、`narrative_role`、`source_refs`、`page_span` 与 `navigation_state`。

## 装配位置

该模块必须紧随 `front-and-ending.cover`，并位于第一章 `chapter-agenda(ch1)` 之前：

```text
front-and-ending.cover → whole-deck-overview → chapter-agenda(ch1) → content instances in ch1
```

之后每个章节仍必须保有自己的 `chapter-agenda`，并按“目录 → 对应章节内容 → 下一章目录”的顺序装配。禁止先堆放全局与所有章内结构页、随后才插入内容页。

## 页码同步职责

- 预排版时，从规划器接收每章预计起始页或预计页段，明确标记其为待终版同步的信息；
- 拆页后，使用最终 `structure-map` 重写每章的起始页/页段，保持章节范围与实际内容一致；
- 当任一前置章节的内容页数变化时，更新所有受影响的后续章节页码；
- 不覆盖或删减 `chapter-agenda` 所维护的本章独立 `section_id` 页段。

## 失败条件

- 位置不在封面之后，或未列全每个章节；
- 改变用户/来源给出的章节顺序；
- 缺少章节语义范围、只显示不透明代号，或页码/页段与最终内容不一致；
- 将全局总览当作章内目录的替代品，或集中生成全部结构页后再排内容；
- 把研究结论、内容字段布局或未经来源支持的内容加入目录页。

## 核心契约依赖与资产

本模块仅依赖 `core-contract`，并遵循来源忠实、来源与备注、视觉与可读性要求；它不依赖其他结构或内容模块。注册表中的独立模板资产路径为 `assets/modules/whole-deck-overview.pptx`。

## 模板占位词

模板资产的待替换文字使用 `章节标题`、`章节范围`、`页码范围`、`来源页码` 等引导字段；不得写入具体研究名称或结论。实际汇报中再按冻结的 `structure-map` 和最终页码替换。
