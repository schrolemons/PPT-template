# 工作过程介绍

## 用途

把一个真实存在的研究方法、实验、工程实施或数据处理内容单元呈现为来源支持的顺序或因果过程。模块只依赖 `core-contract`，不调用其他内容模块或结构模块；它不改变章节顺序、不合并相邻用户子部分，完成后只返回自身页面和最终 `page_span`。

## 适用与不适用

适用于原文存在明确时间顺序、状态转变、因果依赖、信息流或输入—处理—输出关系的过程。流程箭头必须只表达原文支持的变化、依赖或信息流。

不适用于静态组件清单、平级研究发现、无先后关系的类别、仅凭常识补全的实验步骤，或为了视觉形式而把相关概念连接成流程。没有真实有序或因果关系时，改用适合实际叙事任务的内容单元，但本模块不直接调用它。

## 输入与输出

每次消费一个过程内容单元和通用字段：`module_id`（固定为 `work-process-display`）、`instance_id`、`chapter_id`、`section_id`、`subsection_label`、`narrative_role`、`source_refs`、`page_span`、`navigation_state`。来源输入包括过程名称/问题、起始输入、按原文顺序的阶段或步骤、每步的输入变化/依赖、模块状态、产出、图或表（如原文提供）及完整来源位置。

输出一页或多页过程页和排版后的最终 `page_span`。结构连接字段保持不变，供结构层定位、维护导航及同步页码；模块内部不会据此重排内容，也不会编排其他模块。

## 稳定字段顺序与结构连接

页面内容按：过程标题与目的 → 起始输入/条件 → 有序阶段或通道 → 每阶段的来源支持转变/状态 → 输出或下一阶段 → 可见来源行。`chapter_id`、`section_id`、`subsection_label`、`narrative_role` 与 `navigation_state` 只连接到冻结的结构映射；`source_refs` 进入来源行和 Notes；最终 `page_span` 回传给结构层。

## 支持变体

独立模板资产路径为 `assets/modules/work-process-display.pptx`。

- `four-step`：仅用于原文存在四个彼此可读的顺序步骤；每步显示序号、名称、必要的输入/转变与产出。
- `seven-eight-step`：用于七或八个来源定义步骤；保留完整编号及顺序，可采用两行等权网格，但不能打散阶段或省略关键转变。
- `dual-lane`：仅在两条真实、可区分且并列仍可读的过程线存在时使用；每条通道各自展示输入、顺序、状态和输出，不能把相关但无并行关系的步骤强排成双通道。
- `stage-matrix`：用于模块、数据或状态随时间阶段进入、更新、冻结、移除或交接的关系。稳定列为`阶段`、`参与项`、`状态/变化`、`输出与下一阶段`。
- `input-process-output`：用于来源明确界定一个整体输入—处理—输出链且内部步骤不需要逐项展开时；处理中仍需呈现来源支持的关键转变，不能用模糊组件链代替。

## 拆页条件

当七/八步仍无法读清步骤名称和转变、双通道任一侧拥挤、阶段矩阵的行列不可辨、一个过程同时包含两个实质子过程、图注与步骤相互遮挡，或必须缩小至不可读字号时，拆分为同一内容单元的连续页面。拆分不得更换章节、合并邻近小部分或改写原文顺序。

## 来源、Notes 与模块内质检

独立模板资产中的待替换文字使用 `过程标题`、`输入`、`步骤标题`、`步骤说明`、`状态说明`、`阶段输出`、`下一阶段`、`来源页码` 等引导字段。模板只显示顺序和字段关系，不预填某项研究的流程；实际汇报再以原文步骤完整替换。

每页保留可见来源行，覆盖步骤、箭头、图表和状态声明。每页 Notes 必须提供完整多句讲稿和 `[Sources]`：讲稿按显示顺序解释过程及其因果/顺序依据，不把相关性说成因果，也不引入来源外步骤。

检查过程是否真实有序或因果；编号、箭头端点和相邻说明是否一致；输入、变化、模块状态与输出是否有来源；所选变体是否与实际过程匹配；所有文字、图表、矩阵均可读；来源和 Notes 是否齐全；拆页后的最终 `page_span` 是否已回传。
