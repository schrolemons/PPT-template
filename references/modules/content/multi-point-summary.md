# 分条分点性质概括

## 用途

将一个包含多个彼此独立、并列且来源支持的要点内容单元呈现为等权概括页。模块只依赖 `core-contract`；不直接调用其他内容模块或结构模块，不改变章节顺序，也不为了节省版面把相邻用户子部分合并。输出一页或多页概括页及最终 `page_span`。

## 适用与不适用

适用于三项或五项并列概览、权重相同的要点列表，或原文已经给出明确分组关系的概览。每个点必须可独立理解，并由各自来源位置支撑。

不适用于有严格先后或因果的流程、需要完整解释问题—方法—证据的要点、权重明显不同的结论层级，或只有共享类别但实际上是多篇论文正式介绍的情况。任何要点一旦需要完整问题、方法、流程或证据解释，就将该点保留为独立 `section_id` 并由结构层安排对应的详情内容模块；本模块不直接调用详情模块。

## 输入与输出

每次消费一个多点内容单元及通用字段：`module_id`（固定为 `multi-point-summary`）、`instance_id`、`chapter_id`、`section_id`、`subsection_label`、`narrative_role`、`source_refs`、`page_span`、`navigation_state`。来源输入包括概括标题、三个或五个点（或有来源依据的分组）、每点简明来源支持表述、每点的来源位置和必要时的分组依据。

输出一页或多页等权概括页面和最终 `page_span`。连接字段使结构层定位本概括及其页码、导航状态；模块不能据此吞并或重新排列独立要点。

## 稳定字段顺序与结构连接

可见字段顺序为：概括标题/范围 → 并列点或分组标题 → 每点的来源支持短句 → 必要的分组说明 → 可见来源行。点的呈现顺序遵循用户或来源顺序。`source_refs` 汇总且能追溯到每点；`chapter_id`、`section_id`、`subsection_label`、`narrative_role`、`navigation_state` 连接结构映射；最终 `page_span` 回传用于目录、导航、页脚同步。

## 支持变体

独立模板资产路径为 `assets/modules/multi-point-summary.pptx`。

- `three-point-overview`：用于恰有三个同等重要、可短句解释的来源支持要点；三块版面等大、标题层级一致。
- `five-point-overview`：用于五个同等重要、均可读的并列要点；不得用字号缩小隐藏单点说明。
- `equal-weight-point-list`：用于数量非三或五、但仍可在一页或拆分页中保持同等权重的独立点列表；每点使用一致字段结构。
- `grouped-overview`：仅在来源或用户明确给出分组关系时使用；组内各点仍保持独立与等权，组标题不应捏造因果或层级。

## 拆页条件

当任何一点需要完整的问题、方法、流程或证据说明，先将其登记为独立详情内容单元并交由结构层安排；当前概括页只保留可读导航性短句。点数、文字量或分组使所有并列项无法保持一致视觉权重与可读性时，拆成连续概括页，或按真实分组拆页。不得以压缩其他点、删除来源或合并邻近用户子部分解决拥挤。

## 来源、Notes 与模块内质检

独立模板资产中的待替换文字使用 `分组标题`、`要点标题`、`要点说明`、`来源页码` 等引导字段。模板不预填具体论文、模型或结论；实际汇报中的每个点仍需保持来源支持、独立可读与同等视觉权重。

每页保留可见来源行，且每个点都能回溯至 `source_refs`。每页 Notes 必须有完整多句讲稿和 `[Sources]`，按显示顺序解释各点为何并列、它们各自能支持到什么程度，并指明需要详情页时的边界；不可把讲稿留在可见页。

检查所有点是否真为独立、平级且来源支持；是否误把过程或层级关系排成并列点；所有点是否拥有一致视觉权重和完整可读短句；分组是否有明示依据；需要详解的点是否没有被硬塞在概括页；来源、Notes 和最终 `page_span` 是否完整。
