# 论文阅读展示

## 用途

将一个可独立寻址的论文、方法或方法比较内容单元转化为一页或多页来源忠实的学术汇报页。它负责让听众读懂研究对象、原文支持的问题、方法/实现、流程或比较关系；不把相邻论文或用户列出的相邻小部分拼成一页，也不把一个论文的细节改写为另一个论文的结论。

本模块只依赖 `core-contract`，不直接调用任何其他内容模块或结构模块。结构层只提供位置、导航与页码同步，不能调整下述内容字段的语义或顺序。

## 适用与不适用

适用于正式介绍一篇论文/方法、解释其训练或推理流程、说明关键接口、追踪模块跨阶段参与关系，或进行任务明确要求的直接比较。

不适用于纯目录、章节导航、无来源支持的体系结构拼贴、仅为填充模板的 `A+B+C` 组件链，或把多篇正式介绍压缩成一张总览。若内容只是平级短要点，用 `multi-point-summary` 的实例承载；若是目录或导航，由结构层编排相应页面，但本模块不自行调用它们。

## 输入与输出

每次只消费一个内容单元及通用连接字段：`module_id`（固定为 `paper-reading-display`）、`instance_id`、`chapter_id`、`section_id`、`subsection_label`、`narrative_role`、`source_refs`、`page_span`、`navigation_state`。输入还必须包含可追溯的论文/研究名称、原文位置、可见来源行和 Notes 的讲稿依据。

按所选变体补充下列来源输入；未在原文出现的字段不显示，也不得由版式空位推断生成：

- 论文总览：论文/研究名称、清晰原图及其来源、一句话概括、问题、优化/实现、实际意义、研究对象或机器人形态；
- 流程：阶段名称、阶段输入、按原文顺序的步骤、更新/冻结或保留/移除模块、阶段输出/动作；
- 关键接口：待回答的因果问题、输入、转换、输出、下游用途及对应原图；
- 阶段矩阵：阶段、参与模块、更新/冻结/移除状态、阶段输出；
- 直接比较：比较对象、统一比较维度、各对象的来源支持内容与证据边界。

输出为一页或多页来源忠实幻灯片，并在排版结束后返回最终连续页段 `page_span`。若拆页，仍保留同一 `instance_id`、`section_id` 和连续的 `page_span`；不改变章节顺序、不合并邻接小部分。

## 稳定字段顺序与结构连接

通用连接字段始终用于定位和装配，但不占用研究内容层级。可见内容的稳定顺序为：标题中的论文/研究名称 → 一句话概括或页面问题 → 来源图/按序流程/比较主体 → 解释字段 → 可见来源行。`chapter_id`、`section_id`、`subsection_label`、`narrative_role` 和 `navigation_state` 供结构层放置当前章节与导航状态；`source_refs` 支撑可见来源行与 Notes；最终 `page_span` 回写给结构层同步目录、导航、页脚和过渡语。

## 支持变体与版式规则

独立模板资产路径为 `assets/modules/paper-reading-display.pptx`。其权威变体如下；资产建立前，本说明定义其应承载的页面职责，而不是以旧综合库替代新资产。

### `paper-overview-left-figure-right-content`

用于论文/研究的首个正式介绍页。论文或研究名称必须显著；左侧放置占据主要面积、在全页渲染中仍可读的来源原图；右侧依次呈现来源忠实的一句话概括、`问题`、`优化/实现`、`实际意义`，以及原文存在时的`研究对象/机器人形态`。解释必须解读已显示原图中的要素、关系或阶段，不能借图引入无关事实。图中文字或标签不可读时，拆为图页与详情页，或扩展原图区域，绝不缩小图以硬塞字段。

### `training-workflow`

用于实质性的训练或数据准备序列。按稳定顺序呈现：训练输入 → 编号且有来源的步骤 → 每一步的转变/依赖说明 → 更新模块与冻结模块 → 训练阶段输出。箭头只表示原文支持的转变、依赖或信息流，并与箭头端点和相邻解释一致。组件列表和 `A+B+C` 不能替代时间顺序。

### `inference-workflow`

用于实质性的运行时或部署序列。按稳定顺序呈现：运行时输入 → 编号且有来源的步骤 → 保留模块与移除模块 → 推理输出、预测或动作。训练和推理只要任一序列较长、字段较多或并列后标签不可读，就分为独立训练页和推理页；不可用模糊的部署箭头省略运行时变化。

### `training-inference-dual-lane`

仅当训练与推理两条序列都足够短、两侧均能完整展示输入、顺序步骤、模块状态与输出时使用。每条通道分别保持上述字段顺序和可读编号；任一通道拥挤、步骤需解释或图标签不可读时，改用两个独立流程页。双通道不能把训练和推理混成同一条流程。

### `key-interface`

用于回答一个明确的因果接口问题。页面按问题 → 输入 → 转换 → 输出 → 下游用途组织，相关来源图占据足够阅读面积。任何“为何需要该转换”的解释必须对应图中可见元素和原文证据；没有可验证的因果链时不用本变体。

### `stage-participation-matrix`

用于表达模块随阶段进入、更新、冻结、保留或移除的时间关系，不用于静态组件罗列。稳定列为：`阶段` → `参与模块` → `更新 / 冻结 / 保留 / 移除` → `输出与下一阶段`；阶段按来源顺序排列，并明确部署时被移除或保留的模块。

### `direct-comparison`

仅用于比较本身是该内容单元叙事任务时。保持对象与比较维度的可追溯配对，使用表格或成对字段表达非方向性差异；不得以此替代各论文需要的正式介绍。比较结论、解释和证据边界需在可读层级中分开。

## 拆页条件

出现任一情况即增加页面，并让最终 `page_span` 覆盖全部页：来源图标签在全页不可读；一张页同时承载实质训练与推理流程；任一流程的输入、顺序、模块状态和输出无法完整显示；关键接口需要图与解释同时被压缩；矩阵列/行无法辨识；或直接比较使证据说明退化为关键词。拆页只扩展同一内容单元，不能改变 `chapter_id`、合并邻近 `section_id` 或调整用户给定顺序。

## 来源、Notes 与模块内质检

独立模板资产中的待替换文字使用 `论文名称`、`一句话概括`、`发现的问题`、`优化实现`、`实际意义`、`应用对象`、`输入`、`步骤标题`、`步骤说明`、`输出`、`证据边界`、`来源页码` 等引导字段。模板不得预填具体论文名、模型名或研究结论；实际汇报必须用指定原文中的完整、易读语言替换这些字段。

每页必须保留可见来源行，列明支撑该页图、文字、流程顺序与比较项的 `source_refs`。每页 Notes 必须含完整、可直接朗读的多句讲稿和 `[Sources]`，讲稿说明图、流程或表实际展示的来源事实，并明确原文未证实的边界。不可将讲稿残留在可见页。

交付前逐页检查：论文/研究名和一段话是否可读；原图是否真为来源图且标签可读；字段是否按对应变体的稳定顺序呈现；每条箭头是否具有来源支持且与相邻解释一致；训练/推理的更新、冻结、保留、移除与输出是否明确；比较是否没有冒充正式介绍；每页来源与 Notes 是否完整；所有拆分页的最终 `page_span` 是否已回传。
